# Two Windows in One

Разработчик [qqew666](https://github.com/qqew666).

Лаунчер на Rust для Windows 10 и 11 x64. Открывает второе окно под текущим пользователем в приложениях, которые поддерживают такой запуск. Для ряда программ создаёт отдельный профиль и может встроить совместимое окно в рабочую область.

[Скачать установщик](https://github.com/qqew666/wo-Windows-in-One/releases/latest/download/Two-Windows-in-One-Setup.exe) · [Портативная сборка](https://github.com/qqew666/wo-Windows-in-One/releases/latest) · [Сайт и ключ](https://twi.wtowindowszuz.chatgpt.site/)

## Установка и активация

1. Запустите установщик. Он добавит ярлык в меню «Пуск» и запись в «Установленные приложения» текущего пользователя.
2. Пройдите CAPTCHA на сайте и вставьте ключ из 10 символов в приложение. Для проверки короткого ключа нужен интернет. Приложение сохраняет подписанное подтверждение и использует его до ближайшей полуночи по Москве.
3. В меню **Обновления** последовательно проверьте релиз, скачайте его и запустите установщик. Лаунчер сравнивает SHA-256 файла с данными GitHub и освобождает встроенное окно перед своим закрытием. Если загрузка не удалась, кнопка **Релиз в браузере** открывает страницу GitHub или ссылку на установщик. Установщик заменяет предыдущую установленную копию в той же папке. Портативная копия может перейти на установленную версию через тот же установщик.

На сайте можно скопировать длинный ключ для версий 2.1 и старше. Новая версия также принимает этот формат.

## Второй экземпляр

1. Оставьте первое окно открытым. Выберите программу из списка или укажите её файл `.exe`.
2. Оставьте режим **Текущий пользователь** и нажмите **Открыть второе окно**. Для Chrome, Edge, Brave, Chromium, Vivaldi, Firefox, VS Code, VS Code Insiders, VSCodium и Notepad++ лаунчер создаёт новую папку профиля в `%LOCALAPPDATA%\TwoWindowsInOne\Profiles`. Для Word, Excel и VLC использует штатные параметры запуска отдельного экземпляра.
3. Для остальных `.exe` можно указать аргументы из документации программы в разделе **Параметры запуска**. Программа сама решает, открыть второе окно, создать вкладку или переключиться на существующее окно. Лаунчер сообщает, если новое окно не появилось или во время запуска закрылось прежнее.
4. Второе окно по умолчанию открывается отдельно. Можно включить встраивание совместимого окна нового процесса. Окна, созданные уже работающим процессом, остаются на рабочем столе. Кнопка **Отсоединить окно** возвращает встроенное окно на рабочий стол.

### Запуск под другой учётной записью Windows

Откройте **Другие способы запуска** и выберите **Другой пользователь Windows**. Укажите имя второй локальной учётной записи, например `.\Второй`. Команда Windows Runas запросит её пароль в отдельном окне. Приложение получает файлы и настройки второй учётной записи в рамках той же системы. Windows Home тоже поддерживает этот способ.

Если второй учётной записи ещё нет, её можно создать через кнопку **Учётные записи Windows**. Добавление пользователя требует прав администратора. Нужен пароль этой учётной записи, а программе должен быть доступен её файл из второй учётной записи. Некоторые приложения ограничивают число экземпляров по всему компьютеру. Для них остаётся отдельная среда Windows Sandbox.

### Windows Sandbox

Откройте **Другие способы запуска** и выберите **Windows Sandbox**. При выборе установщика `.msi` этот режим включается автоматически. Песочнице нужна поддерживаемая редакция Windows Pro, Enterprise или Education и аппаратная виртуализация. [Инструкция Microsoft](https://learn.microsoft.com/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-install)

Выберите перенос одного файла `.exe` или `.msi` либо разрешите чтение показанной папки с файлами программы. Песочница работает отдельно от основной Windows и удаляет гостевые данные при закрытии. Для работы с облаком можно разрешить интернет перед запуском. Некоторым приложениям нужен установщик. Программы с драйверами или запретом виртуальных машин могут быть несовместимы.

## Сборка

Установите стабильный Rust и средства сборки Visual Studio с поддержкой C++. Из корня репозитория запустите проверку и сборку.

```powershell
cargo test --locked --manifest-path app/Cargo.toml --target x86_64-pc-windows-msvc
cargo build --locked --release --manifest-path app/Cargo.toml --target x86_64-pc-windows-msvc
```

Исполняемый файл появится в `app/target/x86_64-pc-windows-msvc/release/TwoWindowsInOne.exe`. Установщик собирается Inno Setup из `app/installer/TwoWindowsInOne.iss` с параметром `/DAppVersion=2.4.0`. GitHub Actions тестирует установку, повторную установку и удаление и публикует установщик и ZIP после отправки тега.

## Сайт

`site/` содержит статические страницы. Адрес API для GitHub Pages указан в `site/settings.js`. Рабочий сайт с CAPTCHA и активацией обслуживает Worker из `backend/`. Команды `npm ci && npm run build` собирают `dist/server/index.js`. Для самостоятельного размещения задайте `TWI_SITE_ORIGIN`, `TWI_CAPTCHA_SECRET` и `TWI_SIGNING_PRIVATE_PEM`. Открытая часть закрытого ключа RSA 2048 в формате PKCS#8 должна совпадать с `app/license-public.pem`.

Сайт и API можно разместить на одном сервере с Node.js 22+. После сборки запустите `npm start`. По умолчанию сервер слушает `127.0.0.1:8080`. За HTTPS-прокси задайте `TWI_PUBLIC_ORIGIN` равным публичному HTTPS-адресу. Для контейнера задайте `TWI_HOST=0.0.0.0`, а порт при необходимости укажите через `TWI_PORT`.

При переносе сохраните действующий ключ подписи. Если приложение не может связаться со своим сервером активации, на новом сайте можно получить длинный подписанный ключ через раздел **Ключ для версии 2.1 и старше**. Версия 2.4.0 проверяет длинный ключ локально.
